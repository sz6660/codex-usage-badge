# Windows 安装说明（0.10.4）

将 ZIP 完整解压到新文件夹，先确保原版 Codex 已经运行过一次。不要直接在 ZIP 内执行。

只需要三个入口：

| 命令 | 用途 |
| --- | --- |
| `Install.cmd` | 安装或覆盖升级插件，自动备份并设置环境变量，启动插件后台 |
| `Status.cmd` | 查看是否安装、环境配置、后台状态及当前窗口连接情况；不会启动 Codex |
| `Uninstall.cmd` | 停止插件后台、移除自动启动、恢复安装前的环境变量，并清除可连接窗口中的插件界面 |

安装完成后，由你完全退出 Codex，再点击原来的商店／系统图标启动，等待约 5–10 秒。安装器和插件都不会关闭、启动或重新打开 Codex。无需单独执行环境变量命令，也没有冷却期或全局输入保护。若启动器尚未收到环境变更，请注销 Windows 后重新登录。

安装器优先使用客户端自带的 Node.js 24+ 和 Codex CLI；缺少时会提示安装 Node.js 24 LTS。不要以其他用户身份运行安装器。

## 原理和恢复

原入口加载依赖当前客户端的内部环境开关：用户环境中设置 `BUILD_FLAVOR=dev`、回环地址 `127.0.0.1:39222` 的 `CODEX_ELECTRON_CHROMIUM_SWITCHES`，并用 `CODEX_ELECTRON_USER_DATA_PATH` 固定已有配置目录。开发模式也会改变客户端的开发工具和内置更新判断，并非仅增加用量条；未来版本可能不兼容。这不会改写客户端安装文件、快捷方式、聊天或账号文件。

后台只连接已经开放的本机端口来加载界面，不再通过退出重开开启端口，也不查询 GitHub 最新版本。升级时手动下载新包并运行 `Install.cmd`。

重复安装会保留第一次安装前的环境备份。旧实验版的有效备份会自动接管，卸载时恢复实验前的原值；不需要先运行旧卸载器或 Restore-Environment。若这些变量被其他操作改过，安装／卸载会报告冲突并拒绝覆盖。

插件文件位于 `%LOCALAPPDATA%\CodexUsageBadge`；环境备份位于同级 `CodexUsageBadge-Environment`，接管旧实验版时沿用 `CodexUsageBadge-EnvironmentTrial`。卸载后请自行退出并重新打开 Codex，使当前进程恢复原环境；卸载不会替你重启客户端。
